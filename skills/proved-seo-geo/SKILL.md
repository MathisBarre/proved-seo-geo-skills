# Proved SEO & GEO

Use this skill to turn an SEO or GEO request into a source-backed, testable plan. Work from Google Search and Bing documentation first. Treat AI-powered search as an additional surface that shares the same core requirements; do not promise a ranking, citation, mention, click, or conversion.

## Start with the evidence contract

Read [evidence policy](references/evidence-policy.md) and [source registry](references/source-registry.json). Cite source IDs, the relevant source section/locator, and the date you checked it in your working record. Classify every recommendation as one of:

- `primary` — stated by Google, Bing, or IndexNow;
- `secondary observation` — a bounded study that suggests a test;
- `experiment` — a documented local result;
- `heuristic` — a reversible choice that needs validation.

Use the narrowest wording that the evidence supports. State whether a source establishes a requirement, an eligibility condition, an observation, or a proposed test.

Before using an `S-*` secondary source, retrieve the original study/publication and record its method, sample, comparison, date, incentives, and limits. The registry summary is only a routing aid. If those fields are unavailable, omit the secondary claim or keep it as an unvalidated candidate.

## Route the request

| If the request is mainly about… | Read |
| --- | --- |
| Crawl/indexing, URLs, JavaScript, markup, media, or release publication | [technical SEO](references/technical-seo.md) |
| A landing page, site copy, product page, article, release note, video, image, or interactive experience | [content and editorial experience](references/content-editorial.md) |
| Google AI features, Bing/Copilot reporting, citations, visibility, or an experiment | [GEO and measurement](references/geo-measurement.md) |
| More than one of these | Each relevant reference, then combine the recommendations without duplicating them |

## Produce an implementation-ready answer

First establish the page, site, audience, market, intended visitor task, and success metric. Inspect the supplied assets or URLs before claiming a problem exists.

For each recommendation, provide:

1. **Priority and observed condition** — what is present or missing; label an assumption if no inspection is possible.
2. **Change** — a specific technical or editorial action.
3. **Why this is justified** — evidence tier and source IDs.
4. **Limit** — what the change cannot guarantee or where the evidence stops.
5. **Verification** — the crawl/indexing/content/measurement check that could confirm its effect.

For content work, add the visitor question, the factual evidence the page can honestly support, and the appropriate format. A key fact that appears only in an image, video, or interactive demo also needs a clear public textual representation when a search system or visitor must understand it.

For GEO work, define the outcome precisely: eligibility, organic visibility, AI citation, brand mention, referral traffic, or conversion. Measure those separately over time, using only the engine/surface dimensions that the relevant reporting product actually exposes.

## Keep conclusions honest

Use source-backed guidance to make pages more useful and technically understandable. Do not invent fixed targets for word count, heading count, keyword density, media count, schema, FAQs, update frequency, or AI-specific files. Do not treat an AI citation as evidence that the answer is accurate or commercially successful.

When evidence is only secondary, frame it as a hypothesis and propose a controlled or time-bounded measurement plan. When an official source explicitly rejects a tactic, omit it from the recommendation and explain the more durable alternative.
